7.1 Data cleaning

7.1.1 Check the variables

JASP has three options for variable types.

Nominal - categorical with no inherent order

Ordinal - categorical with a meaningful order but intervals between categories are not necessarily equal

Scale - continuous numeric variables with meaningful distances

Tip: Individual items on a questionnaire/Likert scale are often treated as an ‘ordinal’ variable whereas the summed score of all items is often treated as a ‘scale’ variable.

  1. Has JASP automatically assigned the right variable type to each variable? If not, double-click on the header row and change the variable type.

7.1.2 Checking that missing responses are coded correctly

Missing variables can be coded in many ways e.g., ‘.’, ‘99’, ‘999’, ‘-99’, ‘NA’, ‘NaN’ or simply as a blank. JASP as a default considers the following variables as missing: ‘.’, ‘NA’, ‘NaN’ and ‘nan’.

  1. We need to make sure JASP understands which variables are missing/not ‘real variables’. Scroll down enough column and if you spot any missingness indicators that aren’t already covered by JASP’s default settings double-click on the column name and click ‘use custom values’, then enter any variable that should be considered as missing for that column e.g., ‘99’. You should see that this value immediately appears in greyscale on the dataview. To permanently ask JASP to recognise ‘99’ as a missing indicator click on the topleft button -> Preferences -> Data -> Missing value settings and add ‘99’ to the ‘missing values setting’.

7.1.3 Checking data entry

Although entering data by hand is less common nowadays, errors in data entry can still occur. Consider what you know about your variables to think about what would be an impossible or unlikely entry for that variable. For example, it would be unlikely than anyone aged over 110 took part in your study. If we know the range of the questionnaires, for example, the PHQ-9 ranges from 0->3, then it would be impossible for anyone to score a ‘4’ or higher or a negative number on an item. If we find that there is incorrect data entered (and there is no way to identity the correct data for this cell), then we need to treat this item as missing.

  1. Let’s move from data view to analysis. Click on the green ‘Analyses’ button in the topleft corner. Then click on ‘Descriptives -> ’Descriptive statistics’. You will see you now have three panels - data on the lefthand side, data analysis in the middle and output on the righthand side. You can use the arrows and three dots on either side of the analysis panel to change what you can see.

  2. Bring every variable except ‘id’ over from the box on the lefthand side to ‘variables’. You can use ‘Ctrl + A’ to select all variables and then ‘Ctrl’ to deselect ‘id’. Click ‘transpose descriptives table’. Under ‘statistics’, check that ‘minimum’ and ‘maximum’ are selected. Look at each variable. Do any of the minimum or maximums surprise you? Make a note of everything that doesn’t look right.

  3. Click on ‘Tables’ and then ‘Frequency tables’. This number of each distinct entry for nominal and ordinal variables. Is anything miscoded here? Make a note.

  4. You now need to edit the data file to fix these errors. That is called ‘data cleaning’. Whenever you make changes to the file, it is important to not write over the original file. Therefore click on the top left button -> Export Data and then save the file somewhere on your computer. You might want to name this version ‘depression_anxiety_practice_data_v0.1_clean’ or similar. You might also want to include today’s date in the file. Then click on ‘Edit Data’ on the top left button. Find all the cells with impossible/improbable data, click on the cell and clear the data (e.g., by clicking on backspace) so that it becomes registered as missing. If you click on ‘Analyses’ and haven’t closed the file, you will see the analyses will have automatically updated to reflect any changes you have made in the file.

  5. To double-check your data is now ‘clean’, you could use the filter option which is to the left of ‘id’. A box will pop up with variables down the left hand side and a calculator in the middle. Click on ‘age’ then ‘>’ then type ‘110’. Then click ‘apply pass-through filter’. This will highlight all the rows where the participants age is listed as more than 110. If you want to get rid of the filter double-click on the rubbish bin.

Congratulations you have now cleaned your data!

7.2 Missingness

There are three main reasons why data can be missing.

Reason for missingness Description Example
Missing Completely at Random (MCAR) Missingness is unrelated to anything, observed or unobserved A participant’s wifi goes down halfway through the survey
Missing at Random (MAR) Missingness is related to observed variables i.e., something you have measured Younger participants skip an item more often, and age is recorded
Missing Not at Random (MNAR) Missingness is related to the missing value itself People experiencing the most severe suicidal thoughts skip PHQ-9 item 9

When you discover data is missing, you have two options: 1) Imputation, 2) Deletion, 3) Model-based approaches

If your data is MCAR, you can delete the individuals with missing data and analyse only those without missing data (also known as ‘listwise deletion’ or ‘complete case analysis’), however do keep in mind the sample size needed from your power analysis.

7.2.1 Investigate missingness

  1. Have a look again at your Descriptives. Which variable has the highest amount of missing data? Why might that be?

Let’s investigate the missingness of the PHQ9_9 and also learn to calculate variables. Let’s say we want to figure out if those with missing data on the PHQ9_9 also have higher scores across the other items of the PHQ9. We’ll need to calculate a total sum of the other 8 items in the PHQ9 and a binary variable indicating if the PHQ9 is missing or not.

  1. JASP can only add together ‘scale’ items. Change all the items of the PHQ9 from ‘ordinal’ to ‘scale’. Click the green plus at the rightmost side of the columns. Call the column PHQ8_total. Column type should be ‘scale’ and computed type should be ‘computed with drag-and-drop’. Then click on ‘computed column definition’. Add the first eight items from the PHQ_9 together. Remember to click ‘compute column’. Notice how if any item is missing then the summed variable is also missing.

  2. Make a new variable called ‘PHQ9_9_missing’. This should be a nominal variable. Click ‘computed with R code’. Then copy and paste this code into the box that pops up

ifelse(is.na(PHQ9_9), “Missing”, “Observed”)

Remember to click ‘compute column’.

  1. Click on ‘Analyses’ -> Descriptives -> ‘Descriptive Statistics’. Your first analyses should minimise and a new Descriptive Statistics box should open. Split the analyses by your new variable PH9_9_missing. Then bring ‘PHQ8_total’ into variables. Bring anything else that you are interested in seeing whether it is related to the missingness of PHQ9_9 variable. What do you notice? Scroll back up to the table of types of missingness. 7.2.2 Imputation

7.2.2.1 Prorating (person-mean imputation)

One way to address missing data is to impute i.e., replace missingness with a datapoint using an appropriate strategy. If the missing data is related to a questionnaire, the first thing you want to do is check the questionnaire’s instructions. For example, some questionnaires will contain instructions that if one data item is missing, it should be replaced by the participant’s average scores across other items before creating the summed total and may also have a rule that if a participant is missing 2 or more items for a questionnaire, then you should not impute any missing items (i.e., their summed total is treated as missing). It is easy to do this outside of JASP, e.g., in Excel.

7.2.2.2 Mean, median, mode imputation

Rather than replacing a variable at person-level, you can replace a missing item with the average score for that item. For example, you could calculate the average of the PHQ8_total item you created a replace all missing items with that average. However, this shrinks variance and weakens correlations. It is also only truly appropriate in data that is assumed to be MCAR.

If the variable is categorical, then the equivalent is ‘mode imputation’ where you take the most common variable and use that for imputation.

7.2.2.3 Multiple imputation

Multiple imputation creates several completed datasets (often 20 or more), each with slightly different imputed values reflecting the uncertainty. You analyse each one and pool the results using Rubin’s rules, so the standard errors account for imputation uncertainty. This is not possible in JASP (yet!) so you would need to use R and the ‘mice’ package to use this method. This approach assumes data is MAR.

7.2.3 Deletion

Deletion methods are used within analyses.

7.2.3.1 Listwise deletion/complete case analysis

Listwise deletion/complete case analysis removes any person from the analysis who has missing data in any variable. This approach is only appropriate if data are MCAR, however removing participants from your data will affect power.

7.2.3.2 Pairwise deletion

Pairwise deletion is also available as an option in JASP called ‘exclude cases per dependent variable’. The difference with listwise deletion is that when you are computing multiple analyses, participants are only excluded from analyses where there is missing data.

7.2.4 Model-based approaches

It may be the case that you can leave your data as missing for now until you get to the analysis stage. For example in structural equation modelling, and multilevel/mixed-effects models, full information maximum likelihood (FIML) estimates the model using all available data from each case. This approach assumes data is MAR.

7.2.5 Sensitivity analyses

All of this information is confusing with no clear answer. Here is a guide to use with missing data.

  1. Take time to inspect your data. Use your clinical and practical knowledge to understand why data might be missing.
  2. Use multiple methods to approach missing data. Listwise is rarely recommended, but if you do choose to use it, use another method (e.g., multiple imputation) as well as compare whether the interpretation of your results meaningfully differs.

7.2.6 Quiz

Check your understanding: missing data

Click an answer to see whether it is right and why. You can reset the quiz at the bottom.

1. In a depression survey, male participants are more likely than female participants to skip the mood items, and gender was recorded for everyone. Which type of missingness is this?

The missingness is related to an observed variable (gender), which is the definition of MAR. If it were unrelated to anything, it would be MCAR. If it depended on the person’s own mood score, it would be MNAR.

2. In a survey about alcohol use, the heaviest drinkers are the most likely to leave the “units per week” question blank. Which type of missingness is this?

The probability of being missing depends on the value that is missing (high alcohol use). That is MNAR. It is also the same logic as people with the most severe suicidal thoughts skipping PHQ-9 item 9.

3. In JASP you split the descriptives by PHQ9_9_missing. Participants who skipped PHQ-9 item 9 have clearly higher PHQ8_total scores than those who answered it. What does this suggest?

A relationship with an observed variable is evidence against MCAR. It is consistent with MAR, but it is also consistent with MNAR, because the missing item’s own values are never observed. You can’t prove either from the data alone: the argument for MNAR comes from knowing the item is sensitive.

4. You compare people with and without missing PHQ9_9 data on several variables and find no significant differences (only 6 people were missing). Can you conclude the data are MCAR?

Absence of evidence is not evidence of absence. With a group of 6, only very large differences would reach significance, and missingness could depend on variables you didn’t measure (or on the missing value itself). Look at the sizes of the differences, not just the p-values.

5. A participant answered 8 of the 9 PHQ-9 items. The scoring instructions allow one missing item to be replaced before summing. Which description matches prorating (person-mean imputation)?

Prorating uses the participant’s own responses. Option A describes mean imputation, which is a different method. Always check the questionnaire’s scoring instructions: the number of missing items that is allowed varies by scale, and if more items are missing than allowed the total is treated as missing.

6. What is the main statistical problem with replacing missing values with the variable’s mean?

Every imputed value sits exactly at the mean, so the variable looks less spread out than it really is and relationships with other variables are weakened. It also treats imputed values as if they were real observations, so standard errors are too small. For this reason it is generally not recommended, even when data may be MCAR.

7. Which statement about multiple imputation is correct?

Multiple imputation produces many plausible completed datasets (often 20 or more) and combines the results using Rubin’s rules. It usually assumes the data are MAR, and in R it is often done with the mice package.

8. Which statement about full information maximum likelihood (FIML) is correct?

FIML is not imputation: every case contributes whatever data it has to the model’s likelihood. It is available in methods such as structural equation modelling and mixed-effects models. Like multiple imputation, it does not solve MNAR on its own.

9. A participant is missing a value on variable C only. You run three analyses, using A and B, A and C, and B and C. What happens under pairwise deletion, compared with listwise deletion?

Pairwise deletion keeps more data, but each analysis ends up with a different sample size, which makes results harder to compare. Both approaches generally give unbiased results only if the data are MCAR, and both reduce power, so always check the N reported in your output.

10. Which of the following is the best approach to missing data in a real project?

Choosing your method after seeing which one “works” is a form of p-hacking. Good practice is to inspect the data, think about why values are missing, pre-specify the approach, report it clearly, and run a sensitivity check (for example, comparing complete-case results with multiple imputation). Software defaults often silently use listwise deletion, so check the N.

7.3 Normality

Most models (t-tests, ANOVA, regression) assume that the residuals (errors) are approximately normal, not that every raw variable is normal. A skewed predictor is usually not a problem. A skewed outcome often leads to non-normal residuals, but not always. For example, in an independent samples t-test, you check each group separately; in a regression, you check the residuals. A pooled variable made up of two groups with different means can look non-normal even when each group is perfectly normal. That is why you sometimes check the variables first, and then check again after fitting the model.

Normality of variables is an assumption for many analyses. Occasionally, data will be non-normal. Normality can be assessed in multiple ways:

  1. Descriptively, by looking at skewness and kurtosis

  2. Testing using Shapiro-Wilk. If the test is significant (p < .05), that indicates a departure from normality

  3. Visually by inspecting plots

If you find some indications of a variable being non-normally distributed, it may not be an issue especially if there is a large sample size. If all assessments of normality indicate that the non-normality is severe and the sample size is not particularly large…
